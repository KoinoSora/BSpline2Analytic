# 三角形参数域、微小分段及圆锥对应修正：定向回归

对先前 140 个未认证正例中的三个问题组进行修改与测试：三角形参数域 39 例、结点微小区间 26 例、圆锥对应恢复 8 例，共 73 例。另选 26 个普通成功、退化边、200 控制点压力、负例、无效选项和节点预算案例作为控制。每例修改前后各运行 3 次，最终 73 个目标案例中 66 个恢复通过，7 个仍未认证；控制案例结果全部保持一致。

只使用当前 `ValidateGeneralRationalBoundaries` 和固定 V2 数据。未运行已废弃验证器或旧数据，也没有重新生成测试输入。本轮不等同于重新执行全部 985 例。

## 修改与验收范围

1. **参数域合法性。** 普通四边形仍要求严格一致转向。增加恰有一条相邻零长度参数边、三个不同顶点且面积区间严格非零的三角形分支，并要求对应源边的控制点严格重合。先识别退化，再检查非退化边长度；共线、点域、折叠四边形和非相邻重复顶点仍拒绝。恢复诊断在实际映射发生时收集，避免诊断开关改变拒绝顺序。
2. **空间微小分段。** `microSegmentDiameter` 默认 `1e-8`，允许范围 `[0,1e-8]`，0 表示关闭。只有源段、目标段的连续三维直径上界都不超过该值，且两段笛卡尔积距离上界严格小于 `1e-5`，才能合并认证并豁免切向。不能仅凭参数宽度或采样点距离接受。切分点舍入到端点时，完整保留目标小段并与源端点做上述认证，随后认证剩余对应；没有丢弃结点两侧区间。
3. **圆锥三维对应。** 保留原有二维投影快路径。某条圆锥边的恢复距离检查未通过时，以二维参数为初值，沿同一条 NURBS 参数直线进行最多 6 步三维 Gauss–Newton 修正，每步最多 4 次回溯试探，保持参数在 `[0,1]` 且距离下降。重查整条边采样顺序，后续结点和细分对应使用相同修正。修正只产生对应建议，仍由导出曲线的连续误差样条决定验收。

输出 `GeneralBoundaryPatch::tangentExemptions` 保存每个豁免段的源/目标参数范围、各自直径上界和位置上界。`boundaryTangentUpperBoundDeg` 仅覆盖其余非退化区间，豁免不表示已经证明角度达标。几何容差保持 `1e-5`，其余沿边切向容差保持 `0.1°`，不增加曲面法向检查。未采用扩大细分深度或提高样条次数的办法。

## 测试及耗时

基线为 `1978a9469ea95572fa008f7d965fd3c3a4d5cff6` 的独立源码副本。两版均使用 MSVC Release，在同一机器上串行运行；输入来源认证、输出 SDK 独立审计、来源母面诊断均在算法计时之外。算法总耗时包含分类和全部候选验证，共享 50ms 预算。未锁定 CPU 亲和性，也未假定机器没有其他负载。

表中“中位数”为先求每例 3 次中位数、再求组内中位数；“最大”为该组所有实测运行的最大值，单位 ms。失败例也参与统计。

控制组另有 3 个未认证、1 个无效输入、1 个节点预算退出，修改前后状态一致；节点预算退出不是 50ms 时间预算退出。原来提前失败的微小区间、圆锥案例现在会继续完成更多边界计算，因此其耗时增长包含新增的有效工作。

- 最终版本 **297 次运行全部小于 10ms**，最大 **8.8623ms**；50ms 超限和时间预算取消均为 0。
- 最终版本接受 87 例，共 261 次输出审计全部通过；73 个目标中恢复 66 例，控制组 21 个正例全部保持通过。
- 中间版本的一轮同规模测试曾有 extreme-102 第 2 次运行耗时 **13.9032ms**，其余运行小于 10ms；仍无 50ms 超限。保留该批次原始记录，不以最终批次覆盖。当前测量不能构成任意系统负载下的实时耗时保证。
- 单元检查通过 **9974** 项断言，包括四方向三角形、非法域、微小分段位置超差、目标覆盖缺口、长段不得豁免、禁用及超范围选项、三维对应修正。
- 当前验证器及串联输出审计目标编译通过；本轮未运行串联全量数据测试。

26 个微小区间案例的 3 次运行共记录 318 个切向豁免段。最大源直径上界 `8.81453605247721e-9`，最大目标直径上界 `9.90486028065019e-9`，最大位置上界 `1.058565594845834e-7`。每个豁免段还用 SDK 对源/目标端点和中点交叉采样审计位置；其他采样位置继续审计切向。连续位置保证来自生产误差界，独立采样只是附加检查。

## 证据与复现

逐例结果见 [case-comparison.csv](general-rational-repairs-2026-10-16/case-comparison.csv)，剩余失败见 [remaining-failures.csv](general-rational-repairs-2026-10-16/remaining-failures.csv)，切向豁免见 [tangent-exemptions.csv](general-rational-repairs-2026-10-16/tangent-exemptions.csv)。同目录保存两版原始结果、全部候选尝试、输入及程序 SHA256、执行记录、源码文件 SHA256、中间批次记录和剩余案例诊断；诊断耗时不作为生产性能。

选择名单保存在 `selected-cases.json`。构建 `BSpline2AnalyticGeneralRationalBoundaryTests` Release 目标，单元入口为 `--rational-unit <V2 数据根目录>`。定向批测通过现有运行器调用：

```powershell
$caseKeys = Get-Content docs/testing/general-rational-repairs-2026-10-16/selected-cases.json | ConvertFrom-Json | ForEach-Object { "$($_.suite):$($_.id)" }
python tests/RunGeneralRationalBoundaryFull.py --exe <Release程序路径> --sdk ../../../SGGK --data tests/data/general-rational-v2 --output <新的输出目录> --runs 3 --cases $caseKeys
```

运行器只接收 V2 数据，默认 `--max-case-ms 50`。`micro_merged_segments` 统计候选验证中已合并认证的小段次数，`tangent_exemption_count` 是最终输出实际携带的豁免段数；两者不能混用。
