# 等参专用路径：900 个固定案例全量回归

日期：2026-10-16。算法基线：`8b117b981f59c2abac57787e9204cabfb15b1a35`。
Release x64，MSVC 19.42，SGK 1.7.11。源文件、可执行文件和 900 个输入的 SHA-256、逐例命令均保存于
[manifest.json](results/iso-full-20261016/manifest.json)。

**900 例 × 3 次，共 2700 条最终测量全部完成；无进程超时、执行异常或最终输出审计失败。713 例认证通过，48 例退化拒绝，139 例普通输入未认证。不能将本次回归称为全部通过。**

## 测试范围和计时合同

- Dataset500：500 例，实际表示为 300 个非有理、200 个有理；包含 40 个点边退化案例。全部符合最高五次、控制点严格少于 200 的现行合同。
- 业务尺寸极端集：200 例，110 个非有理、90 个有理；包含 8 个点边退化案例。
- 历史极端集：200 例，110 个非有理、90 个有理；与业务极端集同编号不代表同一输入。
- 两套极端集仍使用各自的固定历史表示合同，分别有 30、5 个输入次数超过五次。本轮不生成、不降次、不修改测试几何；当前母面验证器对超过五次的输入不支持。
- 900 个案例均重新通过来源资格检查。来源连续证书、文件加载、输出采样审计不计入算法时间。
- 非有理路径：`IsoClassificationSearch` 从每个非零节点区间两个子区间起步，失败后继续候选搜索、几何拟合及按需加密；候选交给 `mother::ValidatePrepared`。所有失败候选的成本均累计，不仅统计最后一次成功验证。
- 有理路径：`Recognize`，单独记录分类计算和分类验证。母面验证器的五模块列对有理路径为不适用，不填零。
- `algorithm_ms = classification_compute_ms + classification_validation_ms`。本轮不运行曲面优化器，优化计时留空、`optimization_ran=0`。等参线的几何拟合仍属于分类计算。
- 每例串行运行三次，每次使用新的分析上下文和源缓存；没有逐例预热，也没有缓存命中复验混入结果。与之前有预热的 16 例选测不直接计算速度变化率。
- 五模块互斥：准备、母面位置界、位置细分、边界检查、报告。边界内部的细分计入边界模块。原始行的 `validation_ran` 表示是否进入验证；按非有理案例汇总时，未进入验证的案例贡献零验证工作，而非一次零耗时认证。
- 位置约束保持 `1e-5`，保留四边对应位置认证及 U/V 切向的严格 `0.1°` 联合预算；不直接认证法向，不增加相邻面 G1 检查。
- 没有给专用路径新增 10 ms 或 50 ms 的算法终止上限。120 秒逐例进程看门狗包含初始化和来源认证，本批没有触发。
- 没有运行 `ValidateConversion`、`ConvertApproximate`、一般兜底、已废弃的一般数据或旧验证器。这里是当前专用分类＋验证链路的回归，不是尚未迁移的正式完整转换入口回归。

## 结果

下表要求每个案例的三轮结果一致；“认证通过”还要求测试侧独立审计通过。

| 数据集 | 总例数 | 认证通过 | 退化拒绝 | 普通输入未认证 | 退化诊断不符合预期 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Dataset500 | 500 | 460 | 40 | 0 | 6 |
| 业务极端集 | 200 | 128 | 8 | 64 | 0 |
| 历史极端集 | 200 | 125 | 0 | 75 | 0 |
| 合计 | 900 | 713 | 48 | 139 | 6 |

所有案例的状态在三轮中一致。Dataset500 的 460 个非退化案例全部以来源曲面类型认证；业务集、历史集分别有 1、20 个案例通过另一种解析类型认证，属于短弧/低曲率输入在容差内的替代表示，不能计为同类型恢复。

严格的结果/诊断预期合计符合 **755/900**；测试运行器最终返回 **1**，表示存在未认证或诊断不符合预期，并非执行失败。五模块单测另外通过 **1585 项断言**，见 [unit.log](results/iso-full-20261016/unit.log)。

Dataset500 的 6 个诊断差异均为已标注的退化输入：239、299 返回 `NotCertified`，319、339、359、379 返回 `Unsupported`，没有返回测试期待的 `Degenerate`/无候选。它们都未被接受，但后四个案例仍进行了 8–16 次候选验证，造成约 39–42 ms 的平均耗时。

业务极端集的 64 个普通未认证案例中，27 个输入超过五次，另 37 个不超过五次；另外 3 个高次输入属于退化组。历史集的 75 个未认证案例中，5 个超过五次，70 个不超过五次。低次失败仍包含边界关系不一致、没有候选、母面/矩形对应未认证、非规则圆环候选不支持及有理连续界细分预算不足；不能将这些统称为超时或全部归因于数据次数。

## 测试侧审计修正

首轮完整测试发现业务集 161、163、169，以及历史集 16、17、32、33、41、42、89、161、163、173、181、183 共 15 个接受结果的采样审计不一致。直接使用大世界坐标进行 SDK 导数求值、点相减，会在小导数/小残差中产生消减误差。

测试驱动改为复制源控制网并减去首控制点，同时平移候选原点，在局部坐标中执行原有位置和 U/V 切向检查。该改动只影响计时外审计；原输入、分类器、验证器及所有容差均未修改。随后重新运行全部 900 例三轮。2700 条记录的接受状态、输出距离/角度界及候选数与首轮完全相同，15 例审计差异消失。最终接受结果的采样母面距离最大约 `8.738e-6`，采样联合角最大约 `0.008401°`。

审计修正证据见 [audit-cancellation.csv](results/iso-full-20261016/audit-cancellation.csv) 和 [audit-cancellation.json](results/iso-full-20261016/audit-cancellation.json)。采样审计是独立的交叉检查，不代替验证器的连续证书。

## 修改与复现

只修改/补齐测试目标、全量驱动、运行脚本和测试文档，没有修改 `src/`、`include/` 或固定数据。沿用原先未提交的全量驱动框架，替换其中的旧分类首候选逻辑，并加入极端集资格检查、候选累计记录、稳定的局部坐标审计和失败继续执行机制。

在仓库根目录执行（将 CMake/Python 加入 PATH）：

```powershell
cmake -S . -B build-iso-full-20261016 -A x64
cmake --build build-iso-full-20261016 --config Release --target BSpline2AnalyticMotherDistanceDatasetTests BSpline2AnalyticMotherDistanceTests -j 4
ctest --test-dir build-iso-full-20261016 -C Release -R '^BSpline2Analytic.MotherDistanceUnit$' --output-on-failure --no-tests=error
python tests/RunIsoSpecializedFull.py --exe build-iso-full-20261016/Release/BSpline2AnalyticMotherDistanceDatasetTests.exe --sdk ../../../SGGK --work build-iso-full-20261016/final-cases --output docs/testing/results/iso-full-20261016
```

默认恰为三套全集、每例三轮；`--cases` 仅用于定向诊断。运行时不并行测量。不要执行会间接进入旧验证器的历史 CTest 项。
