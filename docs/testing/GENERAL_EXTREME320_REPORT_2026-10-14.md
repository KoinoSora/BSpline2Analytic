# 一般兜底极端 320 例测试报告（2026-10-14）

> 数据版本说明：本报告及其 CSV 保留初版输入的历史结果。后续按世界坐标 `[-1e6,1e6]^3` 约束修订了大坐标组的 24 个输入，当前 manifest 已更新；变更编号与范围见[数据修订说明](GENERAL_WORLD_COORDINATES_UPDATE_2026-10-14.md)。修订后未重新运行测试，旧结果不适用于这些新输入。

本批 **251/320 通过（78.44%）**，38 例返回转换失败，31 例转换超时。320 个输入全部取得来源误差证书，因此这些失败和超时反映当前实现尚未处理好的正例，不能解释为不存在满足要求的解析面片。

本轮新增案例构造器、独立认证器、逐例运行器及报告，没有修改生产转换算法。只测试本批新输入，未运行旧 500 例、一般 600 例或其他极端测试组。

构造与复现步骤见 [GeneralExtreme320 构造说明](GENERAL_EXTREME320.md)，逐例原始记录见 [完整结果 CSV](GENERAL_EXTREME320_RESULTS_2026-10-14.csv)，输入清单见 [manifest.csv](../../tests/data/general-extreme320/manifest.csv)。

## 输入与执行条件

- 共 160 对解析参数配置，有理 NURBS、非有理样条各 160 个；控制点数 50～148，最高次数 9，56 个输入含点退化边。
- 来源类型：平面 8、圆柱 96、球 72、圆锥 88、圆环 56。局部尺寸按 `[1e-2,1e3]` 约束；大世界坐标组测试平移量 0、1e3、1e6、1e9。
- 所有输入在最终控制网落盘、重新读取后认证。最大来源距离上界为 `9.99327678588639e-7`，小弧组另外满足上界 `<0.1*弓高`。四条目标 PCurve 为线段或点；输入样条允许分片 C0 连接。
- Windows x64、Visual Studio 2022、Release、SGK 1.7.11。生产代码基线为 `2181229ce5fe544497a1da35768e422c47155039`。
- 只调用默认 `ConvertGeneral`：每类 8 次初值尝试、16 个粗评分点、几何容差 `1e-5`。不向转换器提供来源类型、解析参数或目标 PCurve。
- 每例独立进程，外部上限 30 秒，覆盖加载、输入认证、转换及输出认证。超时结果根据日志阶段区分；本次 31 例全部停在转换阶段。

测试在记录完 ID 0～297 后按用户要求暂停；恢复时核对输入哈希和可执行文件未变，从 ID 298 继续。中断中的 ID 298 没有写入正式结果，恢复后重新执行。最终 CSV 包含连续的 320 行及每个输入的 SHA-256。所用可执行文件 SHA-256：

## 分组结果

“通过”同时要求生产连续验收通过、独立面片对应距离上界 `<1e-5`、一次 SDK PCurve 及共享端点检查通过。来源类型不作为硬性成功条件；其他类型通过时仍须满足完整几何与边界约束。

224 例恢复来源类型；27 例返回满足容差的其他类型，分别为圆柱→圆环 14、圆柱→平面 1、圆锥→圆环 8、圆环→球 4。它们不是仅凭评分接受的候选，均通过最终独立认证；若未来要求优先保留来源类型，需要另设类型选择指标。

有理输入通过 126/160，非有理输入通过 125/160。没有输入资格失败、输出认证未决或输出认证超时。成功结果中，独立面片距离上界最大为 `9.960744845172458e-6`；生产几何及边界上界的最大值均为 `4.997626012388016e-6`。

1e9 档控制点的最大坐标 ULP 约为 `1.1920928955078125e-7`，实际存储样条全部仍取得 `<1e-6` 来源证书，不能把这 11 个失败统一解释为输入精度已不足。

例如，普通三角片 ID 136、137 返回非线性 PCurve 诊断；细长圆锥有 9 例最终报告球坐标系恢复预算耗尽。这些信息说明当前候选与坐标系恢复过程未找到已知存在的线性边界解，不能将案例改标为无解。所有返回失败均未发布成功面片；超时则由外部运行器标记，不能声称生产接口已经返回转换失败。

有完整阶段计时的 289 个案例（251 成功、38 返回失败）汇总如下；31 个转换超时的阶段时间保留为 NaN，不参与此表。

全部记录的逐例外部耗时之和为 **1216.587 s（约 20.28 分钟）**，其中 31 个超时占 931.477 s。此数包含进程启动、认证及转换，排除用户暂停间隔、被中断而未写入结果的尝试和事后汇总，不是连续运行的墙钟总时长。
