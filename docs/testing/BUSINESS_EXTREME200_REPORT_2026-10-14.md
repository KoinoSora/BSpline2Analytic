# 业务尺寸极端集 200 例测试报告

日期：2026-10-14。算法基线 `2181229`；本轮仅修改测试数据生成、资格检查、运行器与文档，没有修改生产算法、容差或候选预算。Windows x64、MSVC 19.42、SGK 1.7.11、Release；独立构建目录 `build/business-extreme`。

## 1. 结果总览

**200 个输入全部通过生成资格检查，运行中 200 个记录确认完成重新加载资格检查。总体 102/200 转换成功并通过独立采样复核，其中普通面片 102/192；含点边面片 0/8 成功。7 个模块诊断通过 7/7。**

完整状态计数：`{'same_type_success': 95, 'VerificationFailed': 94, 'process_timeout': 4, 'alternate_type_success': 7}`。失败、接口成功后发现采样超差、超时均保留，未按结果替换输入。普通成功与点边成功分开，不把退化返回当作完成转换。

续跑期间其他工作已更新仓库，并修改一般距离界实现；本批一直使用原指纹的独立二进制，未重新链接那些修改。因此本报告针对 `2181229` 算法基线，不用于验证并行产生的新算法改动。

本轮只复测新业务极端矩阵及其模块诊断；未重新运行 Dataset500、General600 或历史 Extreme200。旧极端集半径范围、控制网和算法版本均不同，不能将两批均值直接解释为算法加速或成功率提高。

## 2. 数据范围与资格证据

矩阵与生成规则见 [BUSINESS_EXTREME200.md](BUSINESS_EXTREME200.md)。主要半径/长度 0.01–1000，世界坐标允许到本批平移档 1e9；192 张普通面片、8 张有严格点边的面片，100 对解析来源。普通边长检查仅有数值舍入余量，不放宽转换误差。

控制点五档各 40 个；实际分布为 50 点 36 例、64 点 4 例、80/110/140/200 点各 40 例。实际表示为 90 个有理面、110 个非有理面，后者包含 10 个直接解析转换的平面；来源标签与实际分支不同。所有非有理拟合输入通过实际表示检查。点边在来源和输入中的整排控制点严格重合，独立 Python 文件审计也已通过。

最大同参数连续配对距离界 **9.88976557425e-07 < 1e-6**。普通输入相对来源 NURBS 的最大采样切向角 **0.018358666°**，最大法向角 **0.018358665°**；生成选择角度小于 0.025° 的拟合次数，最终资格要求小于 0.05°。角度是每非零节点跨度 32 等分采样证据，不是连续证书。

首轮构造试跑发现小尺寸圆柱的距离合格并不保证角度合格，随后补充角度资格条件并提高必要拟合次数；未完成试跑不混入本报告。最终固定数据全部通过资格后，从 0 到 199 重新执行。

## 5. 失败解读与边界

| 最终诊断类别 | 数量 |
| --- | ---: |
| 当前候选边界 PCurve 非直线 | 45 |
| 球参数图恢复未解决 | 31 |
| 当前候选边界几何超限 | 11 |
| 共享样条采样预算耗尽 | 5 |
| 外部单例超时 | 4 |
| 连续几何界或投影正则性未解决 | 2 |

表中按最后一条诊断归类，并非互斥的算法根因。全部未通过记录见 [failures.csv](business-extreme200-2026-10-14/failures.csv)，包含分支尝试链和最后诊断。最后候选错误不能代表此前全部候选的根因；验证预算耗尽也不能解释为不存在可行解析面。范围内仍包含短弧、浅锥、周期参数和退化等困难输入，缩小半径范围不会自动消除问题。

例如 ID 25 的分类与优化合计约 114 ms，而验证约 285 秒；ID 37 通过专用分支连续验收，但验证仍约 142 秒。`SurfaceConversion.cpp` 在专用识别后追加 `ValidateGeneral` 以构造有限边界；`GeneralConversionValidation.cpp` 的区间细分、`GeneralPCurve.cpp` 的参数图尝试都记入验证阶段。`SurfaceSampleContext.cpp` 的 20000 点共享预算也会由验证细分消耗。这说明该批整体慢耗时不能直接归咎于参数优化，后续应针对验证细分和参数图恢复分别定位。

普通与短弧矩阵使用以零附近为中心的角域，部分案例同时跨参数周期接缝；它们不是完全正交的单因素实验。接缝组显式覆盖此条件，后续定位还应做同一几何不同参数域的对照，不能将所有失败都归因于尺寸。

每例外部上限 300 秒，超时阶段值为 NaN，不填零。首轮 CTest 被默认 1500 秒整批时限截断，保留了 ID 0–40 的完整记录；保持输入、二进制和选项不变，先从 ID 41 续跑，完成 ID 52 后按用户指示暂停；恢复后从 ID 53 运行至完成。两次中断都没有将未完成的当例视为失败或超时；最终每个 ID 仅保留一次完整结果。CTest 整批时限已修正为 61200 秒，单例与算法预算不变。本轮完成合规数据更新与如实复测，发现的求解/验收问题保留供后续修复。

五类有偏初值模块诊断均在一次迭代内达到停止余量，解析 Jacobian 对照误差见模块表；这只验证给定初值下的局部模块行为，不保证全流程识别与连续验证通过。
