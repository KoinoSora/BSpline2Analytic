# 业务尺寸范围内的极端测试集

版本：`business-extreme200-v1`。200 个固定输入来自 100 个解析配置，每个配置包含解析转换 NURBS 和非有理重拟合。文件保存在 `tests/data/business-extreme200/`。旧 `extreme200/` 和 Dataset500 保留，用于历史结果追溯。

## 1. 尺度口径与矩阵

用户限定半径、长度等主要几何尺寸为 `[0.01,1000]`，世界坐标可以更大。角度、方向向量和归一化 UV 参数不套用长度范围。资格检查包括有效的母面半径、圆锥截面半径及高度跨度、平面边长，以及最终样条的四条非退化边数值弧长；圆锥本批距顶点的最大轴向距离也不超过 1000。球纬圆半径、圆环内侧间隙等派生量单独由场景定义，不对无效的占位半径字段作判断。

普通边数值长度须在 `[0.01,1000]`，端点仅允许 `1e-10` 的相对数值舍入余量；转换器容差不变。退化边是例外：最终整排控制点必须严格重合，不用短边代替点边。源面的位置和轴向不参与尺寸上限判定。

五类数量分别为平面 20、圆柱 44、圆锥 40、球 50、圆环 46。这是有针对性的压力矩阵，不表示实际业务中的类型频率。偶数 ID 为解析转换、奇数为非有理拟合；新旧极端集的同编号不是同一个几何。实际表示为 90 个有理面、110 个非有理面，因为 10 个解析转换平面本身也是非有理表示。`source_kind` 描述生成来源，实际分支依据 `IsRational()`，两者不可混同。

短弧难度采用 χ=h/ε，ε=1e-5，h=2ρ sin²(θ/4)，反解 θ=4 asin(sqrt(χε/(2ρ)))。ρ 是指定边界圆的半径；球直接限制真实母面半径，圆锥为另一条边留出半径余量，因此名义 1000 不强求每条边界半径恰好等于 1000。

## 2. 来源、控制网和数据资格

SDK 从解析等参矩形生成 NURBS，随后将样条参数域规范化到 `[0,1]²`。非有理输入采用张量 Bernstein 配点拟合，依次尝试 3、5、7、9、11、13 次，圆柱/圆锥/平面的另一方向为三次。选择条件是独立配对连续距离界 `<7e-7`，且普通边界的采样切向、法向偏差均 `<0.025°`。该角度余量仅用于生成，不修改转换验收。

控制网按五档 `[50,79]`、`[80,109]`、`[110,139]`、`[140,169]`、`[170,200]` 配额补点，每档 40 个。若最低拟合次数需要更多控制点，选择该档或后续档可容纳的控制网，并保留实际计数；不能突破 200。本批实际数量在报告中列明，最高档优先覆盖恰好 200。

节点插入、方向变换及点边归并完成后，保存所有控制点、权重、节点、原始解析参数和来源 NURBS。`QualifyExtreme` 在生成及文件重新加载后都检查：

1. 控制点总量 50–200；非有理输入的实际权重表示满足要求。
2. 有效母面尺寸与最终非退化边长合规；退化整排控制点严格重合。
3. `BoundPair` 对实际浮点控制网的同参数连续距离上界 `<1e-6`，覆盖整个参数域。
4. 普通边界相对来源 NURBS 的切向和法向偏差，每非零节点区间 32 等分复核，均 `<0.05°`。生成时更紧的角度余量用于吸收节点处理舍入。

第 3 项是连续距离证明；边长采用 16/32 等分复合 Simpson 对照积分，第 4 项是采样证据，不能表述为连续角度证书。解析真值到浮点来源 NURBS 的差异另由测试采样记录，不能由配对证书自动推出。点边角度不定义，记录 NaN；转换成功后仍检查点位置与其余有定义的边界方向。

生成失败保留资格记录并以非零状态退出，不根据转换器结果更换困难案例。生成器拒绝覆盖非空目录。

## 3. 转换、诊断和统计

仅将样条面交给统一入口 `Convert`，不提供来源类型、半径和解析真值。沿用算法默认选项：距离 1e-5，专用分支切向与法向各 0.1°；通用初值仍每类 8 组。生产算法、预算和容差不因本测试集改变。

成功输出以独立母面距离公式、边界近点搜索、切向/法向采样复核。普通成功区分源类型相同与其他类型；不要求恢复唯一源参数。含点边的成功单列 `degenerate_success`，其角度证据为 `sampled_regular_parts`。转换失败、超差、异常和超时原样保留。通用分支当前仍没有连续角度证书，采样通过不等于全部约束已被连续证明。

三阶段只统计转换调用。读取、资格证明、来源复核及输出采样不计入。按场景、类型/来源、控制点档/来源、普通/退化分别汇总；保留每例分类+优化及每组同一案例的最大联合耗时和 ID。失败例参与本组耗时，超时的未知阶段时间使用 NaN。退化案例不混入普通类型均值；全体合计另列。

7 个模块诊断中，5 个使用本集 ID 5/17/29/41/53，分别给五类真值初值施加偏差，检查尺寸/偏移一级优化与解析 Jacobian。其余 2 个保留原 0.0051 小平面角度拒绝诊断，**仅作为范围外的模块诊断，不属于上述 200 例业务数据**。

## 4. 构建与复现

仓库根目录执行 `.\Build.ps1 -Configuration Release -ExtremeBoundaryOnly`，只构建极端测试程序，运行新的 200 例、7 个诊断及独立数据审计。输出为 `build/business-extreme200-Release.csv`、`build/business-extreme-modules-Release.csv`。原 ClassificationGate 定向回归继续读取历史极端数据，本专项不运行它。

独立生成：在 SDK 工作目录且 DLL 路径已配置时执行 `BSpline2AnalyticExtremeTests.exe --generate-business <新的空目录>`。新目录有 `profile.txt`；`--run` 与 `--modules` 根据它选择正确矩阵，未知 profile 拒绝运行。旧 `--generate` 与无 profile 的历史数据仍使用旧矩阵。

逐例执行使用 `tests/RunExtremeDataset.py --exe <程序> --data <数据目录> --output <结果.csv>`。默认一例一个进程、300 秒外部看护上限；CTest 整批时限为 61200 秒，避免默认 1500 秒提前截断；`--first/--last` 选择 ID 半开区间，`--resume` 仅用于同一算法、同一输入的同批中断恢复。全部失败记录、进程日志和逐等参线拟合诊断保留。

汇总：`python tests/SummarizeExtremeDataset.py <manifest.csv> <results.csv> <modules.csv> <汇总目录>`。脚本返回零只表示记录完整、统计一致，不代表转换全部通过。当前复测使用独立 `build/business-extreme` 构建目录，实际证据和指纹见[本轮测试报告](BUSINESS_EXTREME200_REPORT_2026-10-14.md)。

独立数据审计：`python tests/AuditBusinessExtreme.py tests/data/business-extreme200 --output <audit.json>`。直接解析保存文件，检查身份、节点重数、正权重、实际控制点配额、有效尺寸与严格点边，并保存全部文件 SHA-256；它不调用生产转换器，也不替代重新执行的配对距离证明。
