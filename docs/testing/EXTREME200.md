# 大半径小弧长及补充极端测试集（历史压力矩阵）

2026-10-14 起，`Build.ps1 -ExtremeBoundaryOnly` 改为运行[业务尺寸矩阵](BUSINESS_EXTREME200.md)。本文件与 `tests/data/extreme200/` 保留历史数据定义；复现本矩阵应显式给 `RunExtremeDataset.py` 传入旧数据目录。

本测试集测量当前完整转换入口在局部曲率难辨识、尺度悬殊和参数表示变化下的表现。200 个固定面片来自 100 个解析几何配置，每个配置包含解析转换的 NURBS 与非有理重拟合两个输入。另有 7 个模块诊断。所有文件独立保存于 `tests/data/extreme200/`，不读取旧 500 例或 General600 数据。

## 1. 固定矩阵

设几何容差为 ε = 10⁻⁵，目标圆边界半径为 ρ，弧长为 L，角跨度为 θ。用稳定形式计算弓高 h：

```text
θ = L / ρ
h = 2ρ sin²(θ/4)
θ = 4 asin(sqrt(χ ε / (2ρ)))，χ = h/ε
```

按类型统计：平面 6、圆柱 48、圆锥 42、球 52、圆环 52。`analytic_nurbs` 是生成方式标签；平面和部分极小弧长输入的权重可能数值上全相等，应以 `rational` 字段和实际转换路径判断分支。

核心组固定另一方向：圆柱轴向长度 1；圆锥半锥角 π/6、轴向长度 1；球纬度范围 π/2±0.01、球半径 ρ/cos(0.01)；圆环管半径 0.1ρ、管角范围 ±0.01、大半径 ρ−0.1ρ cos(0.01)。这里 ρ 指指定边界圆半径，不统一等同于球半径或圆环大半径。

## 2. 输入构造与资格

1. 在 SDK 中创建解析面，按指定解析等参数范围执行 `ToBSpline`，将样条参数域规范化到 [0,1]²。
2. 非有理输入采用张量 Bernstein 配点插值。计算前减去一个参考控制点，逐次尝试 3、5、7、9、11、13 次；圆柱、圆锥和平面的另一个方向保持三次。选择通过连续距离界的最低次数。
3. 插入节点补足控制网，每方向至少 8 个点，总数要求在 [50,200]。本批实际全部为 8×8=64 个控制点；没有覆盖整个控制点数量分布。
4. 对需要的配置进行参数方向变换；重新构造规范化节点。保存来源 NURBS、实际输入、解析真值和完整控制网。
5. `BoundPair` 直接对输入浮点控制网做向外舍入的有理 Bernstein 提取，在同参数对应下证明整个面片距离严格小于 10⁻⁶。该条件比单向最近距离要求更强。认证覆盖节点插入及重拟合后的实际输入；不是依赖 SDK 求值点的误差采样。

资格清单还记录四条真实样条边界的数值弧长：逐非零节点区间做 16/32 等分复合 Simpson 积分，并记录两次积分差。范围检查为 [0.005,50000]。**这项是高精度数值测量，不是严格弧长区间证书**；生成参数与端点取值保留了余量。弓高计算同样是配置描述，不作为识别成功的依据。

资格认证不能消除 SDK 解析转样条时的浮点误差，因此另记录输入到已知解析母面的加密采样距离，以及输入与来源 NURBS 边界切向、法向的角度差。权重范围、坐标 ULP 和积分差保存在清单。资格失败保留记录，不替换困难案例；生成器拒绝覆盖非空目录。

## 3. 执行与验收口径

`Convert` 只接收输入样条面和默认选项，不接收真值标签。统一入口尝试有理识别或非有理专用转换，失败后进入通用回退。几何容差为 10⁻⁵，非有理专用模块的边界切向和法向角容差均为 0.1°。

每个成功输出另外做独立数值复核：节点区间内加密取点，使用测试端的母面距离公式；边界点到输出 PCurve 三维像的最近点通过一维区间搜索取得。角度比较使用该最近点的解析边界切向和母面法向，**不假设样条参数与解析角参数线性对应**。该复核可提供超差见证，采样通过不能升级为全域证书。

结果区分同类型成功、其他类型成功、连续验证失败、资格未解决和“接口返回成功但采样复核发现超差”。源类型或源半径不作为唯一答案。通用回退当前不证明连续边界角度误差，因此 `sampled_only` 必须单独报告；`specialized_continuous_report` 表示专用分支已有角度报告，不新增对通用输出的角度证明。

所有数值方向角采用无向夹角；使用 atan2(‖a×b‖,|a·b|)，单位为度。源边界采样覆盖每个节点跨度，输出复核每跨度 32 等分。三阶段计时仅统计转换调用中的 classification、optimization、validation，输入加载、资格认证、额外复核与 CSV 写入不计入。每组联合最大耗时为 **maxᵢ(classificationᵢ+optimizationᵢ)**，同时保留对应案例 ID；不能用两个阶段各自的最大值相加。

`iterations`、`candidates`、`pieces` 是最终结果分支可取得的诊断计数，不能解释为此前所有失败尝试的合计；三阶段时间则由统一入口累计所有尝试。每条 `attempts` 保留分支去向和失败信息。首轮性能记录包含成功与失败案例，不另行筛掉慢失败。

7 个模块诊断包括：从本批五类输入建立偏置初值，比较尺寸/偏移一级优化前后最大归一化误差，以及解析 Jacobian 与三种步长中心差分的相对差；另在 0.0051×0.0051 平面上分别构造 0.15° 边界方向偏差和法向偏差，要求位置验证通过、相应角度验证拒绝。这些真值初值只用于独立诊断，不送入 200 例的转换入口。

## 4. 复现

在仓库根目录执行：

```powershell
cmake --build build --config Release --target BSpline2AnalyticExtremeTests
# 在 SDK 工作目录并配置 DLL 路径后，显式运行旧目录：
# python <repo>/tests/RunExtremeDataset.py --exe <repo>/build/Release/BSpline2AnalyticExtremeTests.exe --data <repo>/tests/data/extreme200 --output <repo>/build/extreme200-Release.csv
# <exe> --modules <repo>/tests/data/extreme200 <repo>/build/extreme-modules-Release.csv
python tests/SummarizeExtremeDataset.py tests/data/extreme200/manifest.csv `
    build/extreme200-Release.csv build/extreme-modules-Release.csv build/extreme-summary
```

专项开关只构建新测试目标，并只运行 `Extreme200` 和 `ExtremeModules`。需要 Python 3.8 或以上；`RunExtremeDataset.py` 将每个面片放在独立子进程中，默认外部看护上限为 300 秒，包含加载、认证、转换和数值复核。该上限不调整算法内部容差或预算。

超时保留 `process_timeout` 记录，未知阶段耗时为 NaN，分组均值和最大值只对已完成计时计算，另外记录缺失数量。因此存在超时的组不能声称已知整组最大分类加优化耗时。任何转换失败、未解决输入、超时或复核超差都会使 CTest 返回失败；完整的失败报告仍写入 CSV。汇总脚本返回零仅表示数据完整、计时算术一致，不代表算法通过。

中断后，可在确认算法和输入不变的前提下，向 Python 执行器追加 `--resume`，保留同批结果的连续前缀；CTest 默认重新运行完整新批次。脚本只清理自己输出目录中的逐例 CSV，不改输入。`BEGIN_CONVERT` / `END_CONVERT` 日志用于判断超时是否发生在转换调用期间。

需要重新构造时，先构建新目标，在 SDK 根目录及相应 DLL 搜索环境下执行：

```text
BSpline2AnalyticExtremeTests.exe --generate <新的空目录>
BSpline2AnalyticExtremeTests.exe --run <目录> <结果.csv> [起始ID 结束ID不含]
BSpline2AnalyticExtremeTests.exe --modules <目录> <模块结果.csv>
```

测试暴露的问题应据分层证据处理：来源证书失败先检查生成；已知源面可行但类型检测失败检查曲线拟合和初值；验证预算耗尽属于证明未完成；成功后的超差见证属于验收缺口。不得把“不通过认证”直接解释为不存在几何解。
