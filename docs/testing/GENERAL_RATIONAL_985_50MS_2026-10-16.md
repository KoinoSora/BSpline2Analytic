## 50ms 约束实现

`GeneralRationalBoundaryOptions::maxTotalMs` 默认 50ms。独立验证调用覆盖全部验证阶段；全量分类入口在分类开始前创建一个共享 `ExecutionDeadline`，在所有候选、恢复、准备和连续认证间复用。候选切换、验证重试不能重置时钟。`SurfaceSampleContext` 的预算指针默认为空，其他未启用预算的模块不受时间取消影响。

采用 `steady_clock` 检查。默认在 **45ms** 触发协作式取消，为当前不可分割操作、栈展开和清理预留 5ms；配置其他预算时预留其 10%，最多 5ms。检查覆盖采样、种子生成/评分、图恢复、目标构建和认证递归。时间取消异常独立于几何候选失败异常，不能被候选失败捕获后继续搜索。

超时返回 `BudgetExceeded`、`timeBudgetExceeded=true` 和 `timeoutStage`，清空输出；不冒充几何超差。CSV 新增 `max_case_ms`、`time_budget_exceeded`、`timeout_stage`、`within_time_limit`。最终总耗时仍大于预算时记录真实超时并拒绝该输出；全量运行器对超过墙钟上限或进程错误返回非零。几何未认证结果由汇总失败清单单独体现，运行器退出 0 不代表所有正例通过。

普通 Windows 调度及同步 SDK 调用不提供硬实时保证；预算机制不能从数学上保证每次函数返回都严格小于 50ms。实际超过上限必须保留在 `over-time-limit.csv`，不能通过裁剪计时制造达标。`--max-case-ms 0` 仅作为明确的不限时诊断选项，本次全量没有使用。
