# BSpline2Analytic 修改后同步 Git

## 用户要求与适用范围

用户已明确要求：以后每次完成本项目的一轮代码修改，都将代码提交并上传到 Git 远端。这是持续授权，无需在每次正常提交或推送前重复询问；用户后续针对某次任务的明确指示优先。

目标仓库为 https://github.com/KoinoSora/BSpline2Analytic，保持私有。通过仓库远端身份识别项目，不依赖 SDK 版本目录名。仅适用于这个项目，不将授权推广到其他仓库。

“每次修改”指一轮完整、可提交的工作，包括相关测试、构建脚本及配套文档，不要求每次编辑或保存文件都生成提交。只读分析且没有文件变更时不创建空提交。

## 必须完成的工作

1. 查看工作区、当前分支和远端，确认本轮变更及已有用户修改。目标远端必须对应上述仓库；HTTPS 或 SSH 地址均可。
2. 执行与修改相称的验证，修复本轮引入的问题。记录实际验证结果，不把尚未通过的检查描述为通过。
3. 明确选择本轮需要提交的文件，保留无关用户修改。继续遵守仓库忽略规则，不加入 SGK SDK、许可证、认证信息或构建产物。
4. 检查暂存差异，创建说明本轮改动的提交。2026-10-26 起，面向 main 的修改使用工作分支与 PR；若当前在 main，保留已有修改并创建明确命名的工作分支。使用工作分支上游；无上游时推送并建立跟踪关系，不直接推送或自行合并 main。遵循 [closed-loop-validation](../closed-loop-validation/SKILL.md)：当前只允许协议演练，正式测试暂不启动。正常推送后创建或更新本轮 PR，交由管理员审阅。
5. 执行普通 Git 推送。仅本地提交完成不算同步完成；不使用强制推送，不覆盖或丢弃远端已有工作，不改变仓库可见性。
6. 查询实际远端分支引用，确认其提交 SHA 与本次推送的本地提交一致。最终回复简要说明分支、提交和推送结果。

## 无法完成时

对于普通网络故障或非快进拒绝，先检查原因并在保留本地与远端工作的前提下恢复；不得通过强制推送或丢弃他人改动来满足同步要求。

如果认证过期、权限不足、验证问题或合并冲突无法安全解决，保留工作，明确报告哪些步骤尚未完成以及需要的用户操作。未核验成功时不能声称代码已经上传。

持续授权不改变工具的沙箱和系统权限要求。需要访问沙箱外目录或使用账号凭据时，走工具规定的权限流程；不要把凭据写入文件、提交或日志。
