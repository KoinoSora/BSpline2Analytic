# 算法文档编写

## 目标与适用范围

依据当前项目的实际实现，编写便于理解、复核和后续实现的算法文档。兼顾数学细节与篇幅，采用“总览—技术展开—总结与缺口”的总分总结构。默认使用中文；用户指定的语言、格式或新约束优先。

如果用户只要求创建、更新本 Skill 或复述要求，完成这些事项即可，不擅自开始算法正文。撰写文档不自动授权修改算法、重跑大规模测试或开展外部调研。

## 用户明确要求

1. 介绍整体算法架构，以及每一个功能子模块的作用、算法内容和运行逻辑，并讨论可能的工程化实现。
2. 提供总体模块流程图和子模块流程图，展示实际执行关系，而非只列模块名称。
3. 结合具体测试案例说明算法如何运行；数学叙述详细、准确，能够与实现和测试证据对应。
4. 叙述干练；同一概念、符号、定义或结论集中说明一次，后文引用，不反复展开。
5. 按总分总组织：读者先理解全貌，再阅读技术细节，最后核对结论、适用边界和遗漏。
6. 使用标准文档格式，标题按层级设置真实样式，字号由高级标题到低级标题递减。
7. 尽可能压缩内容，但不减少关键叙述。保留必要定义、数学推导、算法流程、适用条件、实现与验证依据；通过去重、合并共用说明和精炼措辞控制篇幅，不设默认页数上限。用户另有明确页数要求时遵循该要求。

## 编写流程

### 1. 建立实现与证据清单

- 阅读入口、数据结构、核心函数、参数设置、失败处理和测试结果，记录对应代码版本及测试批次。以当前代码为准，不把历史方案当作现有实现。
- 按算法职责划分子模块，不机械地将每个源文件或工具函数独立成章。用一张表映射“子模块—职责—输入输出—关键实现位置”。
- 标记已实现内容、数学假设、可证明性质、采样或经验性判据，以及尚未实现的工程建议。局部收敛、条件成立下的结论和全局保证不得混用。
- 优先复用可追溯的已有测试。缺少中间量时先查代码和日志；需要新诊断时明确其范围，不为填充文档编造结果，也不默认执行耗时的全量重测。

### 2. 先安排结构与页数

建议采用以下正文结构，可随模块复杂度调整篇幅，必须覆盖上述全部要求：

| 部分 | 应回答的问题 |
| --- | --- |
| 1. 整体架构与问题定义 | 输入、输出、前提、目标、主要分支及模块关系是什么？ |
| 2. 子模块算法 | 各模块做什么、如何计算、何时分支或终止？ |
| 3. 案例执行过程 | 真实输入如何经过上述模块并得到结果？ |
| 4. 工程化实现 | 如何组织接口、数据、性能与数值可靠性？ |
| 5. 总结与缺口 | 已覆盖什么，仍有哪些假设、限制和待验证项？ |

结构按任务调整，篇幅由关键内容决定。图表、公式、来源及必要附录均计入实际页数；避免装饰性封面、重复图表和冗长目录，不以删去关键论证换取页数减少。

### 3. 数学化描述每个子模块

每个子模块至少交代职责与输入输出、数学方法、控制逻辑、适用条件。按需要使用公式和简短伪代码，避免逐行翻译源码。

- 全文建立统一符号表；说明变量所在空间、参数域、单位与角度制。后文直接引用定义。
- 明确对象表示及参数对应关系；区分模型参数、源对象参数、离散采样点与连续几何对象，避免默认两套参数线性对应。
- 拟合或优化模块写出实际目标函数、残差、权重、约束、归一化尺度、活动变量和初始化方式。解释参数更新、Jacobian 来源、步长控制、接受准则、停止与回退条件；代码未使用的理论方法不能写成实现事实。
- 分类与重建模块说明判据、候选生成、排序和歧义处理；验收模块说明误差量的定义、计算方法及其证明范围。
- 准确区分点上误差、采样最大值、平均值、保守上界和连续域证书；区分优化目标、提前停止阈值和最终验收阈值。
- 给出关键公式成立的条件及必要推导，使读者能复核公式如何用于实现；省略与实现无关的教材推导。只为后文需要引用的公式编号。
- 说明数值退化、异常、预算耗尽与失败返回；有依据时给出复杂度或主要开销，不将猜测标为测量结论。

### 4. 绘制执行流程图

- 总体流程图覆盖输入检查、主要路径选择、子模块调用、最终验收、成功与失败出口；必要时标出缓存构建和反馈循环。
- 各功能子模块均有相应流程图；紧密相关的模块可合并到同一幅图的独立分区。简单辅助函数在所属模块图中表达，不为其重复造图。
- 图中明确条件分支、数据流或调用方向、迭代入口、停止条件和失败回退。节点名称与正文、符号和实现名称一致。
- 优先采用可维护的矢量图。Mermaid、Graphviz 等均可作为图源；最终排版文档须呈现可读的图形，不能以未渲染源码代替图。
- 每幅图有编号和简短图注，正文解释图中关键判断，不重复逐个朗读节点。避免跨页拆图和缩小到难以阅读的标签。

### 5. 用案例贯穿运行过程

- 选择少量有代表性的实际案例，优先覆盖不同主分支、需要优化的情况、可直接通过的情况或退化/失败路径。案例数量服从解释需要与篇幅，不要求每一种组合都单列。
- 记录案例编号、来源、关键输入规模和条件、代码版本、测试批次。说明输入检查、分类候选、参数恢复、优化或跳过原因、验收及最终状态。
- 用紧凑表格列出有证据支持的关键中间量、迭代数、误差上界和耗时。只有采集到执行轨迹时才逐步描述实际迭代；理论示意必须明确标注。
- 分开列出分类、优化、验收时间，并注明预热、重复次数、均值/最大值口径。若给出“分类＋优化最大值”，先对同一次运行求和，再取最大。
- 不混用不同批次的结果，不把零优化案例写成优化器验证，也不把预期退化拒绝写成成功转换。案例用于解释机制，不替代一般性的数学保证。

### 6. 工程化与总结

- 工程部分按实际需要讨论接口和数据结构、缓存复用、候选与回退、数值稳定性、计算预算、计时与诊断、测试组织等。明确哪些已经实现，哪些只是建议；不把可选改进写成已有能力。
- 最后的总结不复述整篇正文，以短表核对“模块/要求—实现或证据—限制或待办”。指出尚未覆盖的情形、证据缺口及后续验证方向。

## 排版与篇幅控制

- 使用用户指定的交付格式；未指定时，选择能够分页并核验页数的正式文档格式。Markdown 可用于中间稿；最终报告实际页数，不凭字数估算冒充排版结果。
- 使用编号标题、统一字体与正文样式、页码、公式/图/表编号及必要的交叉引用。高级标题字号大于低级标题；同级样式一致，图注与正文层次分明。
- 可采用 A4、正文 10.5–11 pt、一至三级标题约 16/14/12 pt 作为初始排版建议；这不是用户指定的强制数值。保持公式、流程图和表格可读，不靠极小字体或异常窄页边距压缩。
- 完成后渲染并核验实际页数及所有页面，检查标题层级、图表、公式、分页、截断和空白。核验不了时如实说明，不声称页数已确认。
- 排版前后均检查可压缩的重复内容，优先合并共用定义、收紧辅助解释和消除无效留白；保留关键数学步骤、必要流程图及证据边界。不因超过某个默认页数而要求增页批准。

## 交付检查

确认整体架构、所有功能子模块、数学逻辑、总体及局部流程图、真实案例、工程化讨论与总结缺口均有对应内容；符号只定义一次，证据可追溯，已实现与建议分明，格式与实际页数经过核验。交付时说明文件位置、实际页数和影响结论的未完成事项。
